# 작성팀(워크스페이스 편집) 기계 채점 평가

고정 LaTeX 픽스처(4파일: main/intro/method/refs.bib + 그림)를 과제마다 새로 만들고,
기계 채점 가능한 지시 10개를 실제 경로(runWorkspaceEdit: 편집→컴파일 게이트)로 실행.
생성물 평가는 정답이 없으므로 **속성 4축을 기계로 판정**한다 (LLM judge 불필요).

|---|---|---|
| ① 컴파일 성공 | **9/10 (90%)** | 편집 후 pdflatex 빌드 성공 (자동 수정 루프 포함) |
| ② 지시 이행 | **9/10 (90%)** | 기대 변경(regex)이 전부 반영 |
| ③ 보존성 | **10/10 (100%)** | 변경 파일이 허용 목록 안에만 있음 |

## 실패 2건 분석

- **t01 (인용 유효성 ❌)**: 에이전트가 새 동기 문장에 **빈 `\cite{}` 2개**를 넣음 — 이는 버그가
  아니라 **작성팀 스타일 규칙 5번("인용 필요 자리엔 오직 빈 `\cite{}`", 인용 에이전트가 나중에
  채움)을 따른 의도된 동작**이다. 컴파일도 통과([?]로 렌더). 즉 이 축의 위반은 "앱 설계(placeholder)
  ↔ 평가 축(키 실재)"의 충돌로, 실재하지 않는 키를 지어낸 진짜 위조는 **0건**이다.
  (개선 여지: placeholder는 별도 집계로 분리하면 축이 더 정확해짐.)
- **t03 (이행 ❌)**: 에이전트가 파일을 수정하지 않고 **읽기 전용 답변**으로 끝남(read_only) —
  "인용을 추가해줘"라는 명시적 편집 지시의 미이행. 이 하니스가 잡으라고 만든 실패 유형의 실례.

실행 레코드: `eval/runs/write-eval-*.json` (편집 후 파일 전문 포함, 로컬).
데이터 격리: `PAA_DATA_DIR=eval/runs/write_eval_data` — 앱 라이브러리와 분리.
